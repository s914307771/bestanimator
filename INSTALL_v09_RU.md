# Double Bubble Show CRM v0.9 — сотрудники, личные кабинеты, доступ к оплатам и расходам

Статус: **пакет исходного кода, ещё не установлен в Supabase/Vercel**. Сохранены действующие таблицы заказов, клиентов, персонажей, платежей и расходов. Перед запуском требуется тестирование в Preview.

## Что изменилось

- Личный кабинет владельца и менеджера: сводка заказов, поступлений, этапов исполнения, смена пароля.
- Раздел «Исполнение»: этапы каждого мероприятия, комментарии, кто и когда отметил действие, журнал изменения статуса заказа.
- Раздел «Сотрудники и права» — только у владельца: приглашение сотрудника на email, индивидуальные разрешения, история выдачи прав.
- Дима (новый менеджер): по умолчанию может создавать заказы, менять обычные статусы, отмечать исполнение, **принимать оплату, видеть платежи, добавлять/редактировать расходы, видеть финансовую историю**.
- Дима по умолчанию **не может** отменять заказы, утверждать закрытие заказа, оформлять возвраты, отменять расходы, управлять другими сотрудниками или правами. Эти действия можно дополнительно разрешить владельцем (кроме управления сотрудниками).
- Ограничения реализованы в Supabase PostgreSQL RLS и триггерах, а не только в интерфейсе. Действующие платежи и расходы остаются в своих таблицах; audit v0.7 сохраняется.

## Установка (сначала тестовая ветка)

1. В GitHub `s914307771/bestanimator` создайте **новую ветку от актуальной `main`**, например `feature/owner-manager-cabinets-v09`. Не заменяйте файлы в `main` до тестов.
2. Из архива перенесите в новую ветку, с сохранением **точных путей**:
   - `best-animator-cloud/app/page.tsx` (замена)
   - `best-animator-cloud/app/globals.css` (замена)
   - `best-animator-cloud/app/layout.tsx` (замена)
   - `best-animator-cloud/app/api/staff/invite/route.ts` (новый файл)
   - `best-animator-cloud/supabase/migration_v0.9_staff_permissions.sql` (только файл, **не запускается автоматически**)
3. В Vercel для проекта `best-animator-cloud` убедитесь, что Preview получает `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Не добавляйте приватные ключи в GitHub!
4. В **Vercel → Settings → Environment Variables** добавьте секрет `SUPABASE_SERVICE_ROLE_KEY` (значение — Supabase Project Settings → API Keys → service_role/secret; только на сервере, **НИКОГДА не `NEXT_PUBLIC_*`**). Выберите Preview для тестирования. Не передавайте этот ключ в чат или переписку.
5. Добавьте `CRM_PUBLIC_URL` с **точным HTTPS-адресом** тестовой версии, например Preview-домен, который Vercel назначил вашей ветке. В Supabase Authentication → URL Configuration внесите его в Allowed Redirect URLs. Примените изменения переменных и пересоберите Preview.
6. Экспортируйте важные таблицы (staff_profiles, orders, clients, payments, expenses, characters) из Supabase перед изменением SQL. Free-план может не включать автоматические бэкапы. Сохраните экспорт вне Supabase.
7. В **Supabase → SQL Editor** запустите содержимое `migration_v0.9_staff_permissions.sql` в том же проекте, к которому подключена CRM. Это изменяет права пользователей действующей базы: обязательно проводить в спокойное время.
8. Запустите `check_v0.9_readonly.sql`. Убедитесь, что создались таблицы, а роль владельца — `owner`. Войдите в новую Preview CRM как владелец.
9. Откройте **Сотрудники и права → Пригласить нового менеджера**, укажите имя «Дима» и его настоящий email. Supabase отправит ему письмо. После перехода по приглашению он сможет зайти и задать пароль в «Мой кабинет». Если Supabase требует настроить email-сервер или Site URL, сначала проверьте эти настройки.
10. В кабинете владельца откройте карточку Димы. Убедитесь, что включены `finance.view_payments`, `finance.record_payment`, `finance.view_expenses`, `finance.create_expense`, `finance.edit_expense`, `audit.view`.
11. Войдите **отдельно в приватном окне** как Дима, на тестовом заказе проверьте фиксацию частичной оплаты и расхода (обязательно проверьте, что суммы и автор отображаются у владельца). Проверьте, что Дима не может создать возврат, отменить расход или заказ, а владелец может.
12. После успешного теста — настройте переменные для **Production**, установите `CRM_PUBLIC_URL` на **постоянный безопасный адрес** CRM, разрешите его в Supabase Auth, и только затем публикуйте через Pull Request.

## Важно

- Никакая учётная запись Димы этим ZIP не создана: его реальный email пока неизвестен, приглашение отправляется владельцем только после установки.
- CRM v0.9 нельзя считать протестированной, пока Next.js успешно не собрался в Vercel и не проверены обе роли. Для проверки синтаксиса TSX выполнена локальная компиляция-транспиляция без доступа к пакетам Next.js; **полный `next build` не выполнялся**.
- Предыдущие предупреждения Chrome «Опасно» и «Проверьте пароли»: используйте постоянный проверенный домен, смените возможный скомпрометированный пароль и проверьте Safe Browsing, прежде чем приглашать сотрудников.
- Файл `rollback_v0.9_rules_only.sql` предназначен только для аварийного отката ограничений на стороне базы при возврате старой версии CRM; он **возвращает более широкие права v0.8** и не удаляет таблицы/историю. После отката не оставляйте менеджерские аккаунты с ненужными правами.
