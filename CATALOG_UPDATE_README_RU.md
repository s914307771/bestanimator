# Double Bubble Show — каталог персонажей для CRM

Версия: адаптация на основе пользовательского архива `bestanimator-main.zip` (07.11.2026).

## Что сделано
- Сохранены разделы заказов, клиентов, календаря, команд, платежей, расходов и уведомлений.
- В разделе «Персонажи» отображаются фото из `characters.image_url`, название, категория, премиальность, публикация и статус.
- Кнопка «Редактировать» открывает карточку и позволяет менять имя, примечания, категорию, URL фотографии, флаги активности, премиальности и публикации.
- Кнопка «Календарь» сохраняет прежний переход к занятости конкретного персонажа.
- Сохраняются существующие ID персонажей и связи с заказами.

## ВАЖНО
- **База не меняется:** SQL запускать не нужно. К этому моменту `characters` уже содержит дополнительные столбцы `category`, `image_url`, `is_premium`, `show_in_app`.
- **Данные не импортируются:** 17 персонажей уже добавлены в Supabase и будут загружаться автоматически.
- **Файлы изображений не входят в этот пакет:** загрузка уже выполнена в Storage, интерфейс берёт `image_url` из базы.
- Два персонажа (SpiderMan, Дед Мороз) остаются без фото, пока URL не добавят через CRM.
- В редакторе можно вставить публичный HTTPS URL изображения. Загрузка файла прямо из CRM пока не реализована (для этого потребуются отдельные Storage RLS-политики).
- Эта версия **не развёрнута на Vercel**. Не заменяйте вслепую текущий production-проект, если в нём были изменения после исходного ZIP.
- Автоматическую сборку локально проверить не удалось: зависимости npm недоступны в офлайн-среде. Проверьте `npm install && npm run build` в своём окружении/на Vercel Preview.

## Безопасное внедрение
1. Сохраните копию актуального проекта CRM на GitHub и при необходимости текущие две версии файлов `app/page.tsx`, `app/globals.css`.
2. Сравните эти два файла из архива с **актуальной**, а не исторической версией CRM. Если ваш production после 07.11 изменялся, перенесите только изменения из `app/page.tsx` и `app/globals.css`, не заменяя новые функции CRM.
3. Создайте тестовую ветку в GitHub (`feature/character-catalog`) и скопируйте два файла в проект.
4. Проверьте Vercel Preview: авторизация, список 17 персонажей, изображения 15 героев, редактирование категории/имени/примечаний; создание заказа и календарь; отсутствие ошибок в логах.
5. Проверьте политики RLS в `public.characters`: текущий сотрудник должен иметь права `SELECT` и `UPDATE` для этой таблицы. Если обновление возвращает ошибку, не отключайте RLS — уточните политику доступа.
6. После успешной проверки внесите изменения в main/Production.

## Как работает
Источник: `public.characters` в Supabase. Выбор персонажей в Mini App отдельно фильтруется по `is_active = true` и `show_in_app = true`.

## Файлы
- `app/page.tsx` — страницы и логика CRM с редактором персонажей.
- `app/globals.css` — стили карточек и формы.
- Остальные файлы исходного проекта сохранены без изменения.
