# BEST Animator CRM v0.4 — блокировка двойных бронирований

1. **Сначала** Supabase → SQL Editor → New query: выполните `supabase/migration_v0.4_no_overlaps.sql` (НЕ `schema.sql` заново). SQL ничего не удаляет. В конце выводятся уже существующие конфликтующие заказы; устраните их вручную, изменив статус одного на «Отменён» либо согласовав другое время.
2. **Затем** замените исходники GitHub на обновлённую версию из этого архива. Если в GitHub проект лежит в подпапке `best-animator-cloud`, обновляйте файлы именно внутри неё, а не в корне репозитория.
3. Дождитесь успешного Deploy на Vercel. Переменные Supabase остаются прежними.
4. Проверка: забронируйте событие 16:00–17:00, попробуйте создать второе в 16:30–17:30 — должно отклонить. 17:00–18:00 — разрешить. Сделайте тест также в двух браузерах/на разных телефонах.

Важное ограничение v0.4: одновременно может идти только ОДНО мероприятие компании, даже если аниматоры разные. Это временная безопасная политика, пока не введён модуль распределения команд и костюмов.
