# BEST Animator Cloud v0.5 — персонажи и команды

## Установка на существующую CRM
1. Сделайте резервную копию Supabase (перед миграцией). НЕ запускайте schema.sql повторно.
2. Supabase → SQL Editor: выполните `supabase/migration_v0.5_resources.sql`. **Если ранее выполняли v0.4, миграция удаляет глобальную блокировку**, заменяя её правилами по командам и персонажам.
3. В GitHub замените файлы приложения в **том же Root Directory**, что указан в Vercel. Не загружайте папку поверх папки так, чтобы получилась двойная вложенность.
4. Vercel автоматически развернёт новый коммит (или запустите Redeploy). Переменные Supabase сохраняются.
5. Добавьте активных персонажей и команды. Проверьте один и тот же персонаж не может быть забронирован дважды. Два разных персонажа с разными командами — допускаются.

## Важные ограничения
- Старые заказы v0.3/v0.4 НЕ получают персонажей и команды автоматически. SQL в конце показывает список таких заказов. До их ручного распределения нельзя считать доступность ресурсов полной.
- Архивирование вместо физического удаления: сохраняется история заказов и платежей.
- Команда сейчас — название и заметки о составе. Индивидуальный учёт конкретных аниматоров и времени в дороге будет следующим модулем.
- Каждая активная бронь обязана выбирать минимум одного персонажа ИЛИ команду; для лучшего планирования выбирайте оба.
- Время занятости считается по длительности самого шоу (без дополнительного времени на дорогу, переодевание). До учёта буферов руководитель должен проверять расстояние вручную.
- Существующие пары конфликтующих заказов не отменяются автоматически.
- Этот релиз не содержит прямого редактирования уже созданных назначений. Старые назначения перепроверяются вручную через Supabase до появления экрана редактирования.
